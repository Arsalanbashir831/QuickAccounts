## Requirements

Implement a **Cash Back, Return, and Replacement flow** for the accounting application in a way that is simple for non-accountants. From a completed sale/invoice, the user should have two actions: **Cash Back** and **Return / Replace**. Cash Back is used when the customer keeps the product but receives some money back due to price adjustment, discount, complaint, overcharge, or goodwill; the user selects the refund amount, reason, refund method, and confirms that no product is coming back. Return / Replace is used when a product is physically coming back; the user selects the original sold item, return quantity, return reason, product condition, and whether the item should be restocked, moved to damaged stock, moved to supplier-return stock, or written off. After this, the user chooses whether to give a full refund, partial refund, no refund, or replace the product. For replacement, the user selects the replacement product and quantity, and the system automatically compares the original returned value with the replacement value. If the new product costs more, collect the difference; if it costs less, refund the difference; if both values are equal, complete the replacement without payment. The original invoice must never be modified or deleted; every adjustment must be recorded separately and linked back to the original sale. The backend must calculate refundable amount, returnable quantity, replacement difference, inventory movement, historical COGS reversal, payment movement, journal entries, and final sale status automatically.
